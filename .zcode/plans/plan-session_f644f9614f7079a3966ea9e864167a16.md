修正 LoadConfig 的默认模型选择逻辑(用户思路正确,实现有三处问题):

1. **core/Core.go — LoadConfig()**:把默认模型选择块从 `resolveEnabled()` 之前移到之后,并加守卫:
   ```go
   resolveEnabled()

   // 启用项没记住模型时默认选第一个，开箱即用；仅在内存中生效，随下次保存落盘。
   if cfg := Platform.Configs.EnablesConfig; cfg != nil && cfg.EnabledModel == "" && len(cfg.Model) > 0 {
       cfg.EnabledModel = cfg.Model[0]
   }
   return nil
   ```
   修复三点:EnablesConfig 判 nil(防空指针 panic)、用 len(Model) > 0 判断(防空切片越界)、移到 resolveEnabled() 之后(否则默认值设在文件拷贝上,归位后丢失)。

2. **tests/configs_test.go — 补两个用例**:
   - 启用项存在且 EnabledModel 为空、模型列表非空 → LoadConfig 后 EnabledModel == Model[0];
   - EnablesConfig 为 nil(无启用项)时 LoadConfig 不 panic 且行为不变。
